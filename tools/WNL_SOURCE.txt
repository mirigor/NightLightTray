Внешний компонент: win-nightlight-cli (wnl.exe), версия 0.4.0.
Проект: https://github.com/kvnxiao/win-nightlight-cli
Коммит: 96fdd61b06ca4fb74dbc2b8368ddc9bd4b77ab03
Лицензия MIT: WNL_LICENSE.txt.

Сборка из исходников без изменений:
Rust 1.99.0, x86_64-pc-windows-msvc, --locked --release,
RUSTFLAGS=-C target-feature=+crt-static.
Повторная сборка: tools/build_wnl.bat (Rust и MSVC Build Tools C++).

NightLight Tray использует только wnl status и wnl temp <KELVIN>.
Шкала сохраняет пересчёт прежнего nightlight-cli: K = 6500 - 53 * процент.
Обратное преобразование округляется до ближайшего целого процента.
Настройки расписания и состояние включения не изменяются приложением.
Начиная с 0.3.0, wnl temp применяет температуру через штатный предпросмотр
Windows, затем завершает предпросмотр. Это исправление ошибки, при которой
сохранённая температура не влияла на экран: issue #11 в исходном проекте.
Ночная подсветка не выключается и не включается для применения температуры.
Если wnl сообщает Windows default, программа не выдумывает интенсивность.

Для исходников wnl.exe находится в tools. build.bat включает его и лицензию
в NightLightTray.exe. Установка Node.js, npm и Rust для запуска этой сборки
не требуется. NIGHTLIGHT_WNL может задать полный путь к другому wnl.exe.

Ручная проверка проблемы 56% и 68%:
1. Запомнить текущую интенсивность в параметрах Windows.
2. В новом NightLightTray.exe выставить 56%, затем 68%.
3. Сверить проценты с системным ползунком и цветом экрана.
4. Вернуть исходную интенсивность.
Чтение подтверждает сохранённую настройку, но не измеряет оттенок экрана.

Диагностика только чтения: .venv\Scripts\python.exe tools\check_wnl.py
